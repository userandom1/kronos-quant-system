Filosofía de desarrollo
El proyecto debe evolucionar como plataforma modular de Quantitative Finance.
Principios:
1. Separación clara de responsabilidades.
2. Arquitectura multi-activo.
3. Módulos reutilizables.
4. Interfaces estables.
5. Type hints.
6. Código legible.
7. Tests.
8. Logging cuando corresponda.
9. Manejo explícito de errores.
10. Evitar duplicación.
11. Evitar dependencias circulares.
12. Mantener compatibilidad cuando sea razonable.
Estilo de código
Aplicar PEP8 adaptado al proyecto.
Preferir:
- type hints;
- dataclasses cuando tenga sentido;
- Enum para categorías cerradas;
- pathlib cuando encaje;
- logging en infraestructura;
- docstrings en funciones públicas o complejas;
- nombres descriptivos;
- funciones pequeñas y testeables.
Evitar:
- except Exception: pass;
- variables globales innecesarias;
- lógica duplicada;
- números mágicos;
- rutas hardcodeadas dispersas.
Tests y validación
Antes de considerar terminado un cambio importante:
1. Ejecutar tests relacionados.
2. Ejecutar tests globales si el coste es razonable.
3. Comprobar imports.
4. Comprobar type checking cuando corresponda.
5. Comprobar comandos principales.
No eliminar tests simplemente para hacer pasar una implementación.
